# DomainがWorkbookRevisionを生成する

Cell単位のEditConflict、Worksheet構造との整合、次のRevision番号はSpreadsheetの業務規則なので、in-memoryやSQLiteのRepositoryで重複判定せず、現在の`Workbook`と`WorkbookChangeSet`からDomainが一度だけ判定して次の`WorkbookRevision`を生成する。UseCaseはWorkbookの取得、DomainによるRevision生成、期待した現在版を条件とするRepository更新を組み合わせ、保存時に別の更新が先行した場合は再取得して同じChangeSetを再評価する。Repositoryは集約のCRUDとcompare-and-swapだけを担う。CellContentを削除したCellも`content: null`と最終変更版を持つCell EntityとしてWorkbookRevisionへ残し、ADR 0003のCell単位の競合規則をDomainで判定できる状態として復元する。
